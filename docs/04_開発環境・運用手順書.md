# 開発環境・運用手順書

## 1. 必要なもの

| 項目 | 内容 |
|---|---|
| Node.js | 22 系（CI は Node 22）。社内 SSL 検査対策の `--use-system-ca` は Node 22.15 以降で有効 |
| パッケージ管理 | npm（`package-lock.json` あり） |
| エディタ | VSCode |
| VCS | GitHub（ブランチ: `main`） |

## 2. セットアップ

```bash
# 社内ネットワークでは先に設定（Windows 証明書ストアを読む）
export NODE_OPTIONS=--use-system-ca      # PowerShell: $env:NODE_OPTIONS="--use-system-ca"

npm ci
npm run dev        # http://localhost:3000
```

### 社内 SSL 検査について
`npm install` / `npx` / `next build` が `UNABLE_TO_VERIFY_LEAF_SIGNATURE` で失敗・極端に遅くなる場合、社内の中間 CA を Node が信用していないことが原因。`strict-ssl false` は検証を無効にするため**使わない**。上記の `NODE_OPTIONS=--use-system-ca` で対処する。

## 3. npm スクリプト

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド（静的書き出し → `out/`） |
| `npm run start` | `next start`（`output: "export"` のため、公開形態の確認には §4 の `out/` 配信を使う） |
| `npm run lint` | ESLint |

## 4. 公開と同じ形での確認

```bash
PAGES_BASE_PATH=/<リポジトリ名> npm run build
# out/ を /<リポジトリ名>/ 配下で配信して確認
```

## 5. デプロイ（GitHub Pages）

- `.github/workflows/deploy.yml`: `main` への push、または Actions タブからの手動実行（`workflow_dispatch`）で起動。
- 流れ: checkout → Node 22 + npm キャッシュ → `npm ci` → `actions/configure-pages@v5`（base_path 取得）→ `npm run build`（`PAGES_BASE_PATH` を渡す）→ `out/` を artifact 化 → `actions/deploy-pages@v4`。
- 権限: `contents: read` / `pages: write` / `id-token: write`。同時デプロイは 1 つ（実行中は中断しない）。
- 初回のみ: リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
- 公開 URL: `https://<ユーザー名>.github.io/<リポジトリ名>/`
- 注意: 無料で使えるのは Public リポジトリ。非公開リポジトリは有料プランが必要。

## 6. 開発ルール（現状の運用）

| 項目 | ルール |
|---|---|
| 画面の文言 | 日本語 |
| コミットメッセージ | `feat:` / `fix:` / `chore:` などの接頭辞 + 日本語の説明（既存履歴に倣う） |
| ブランチ | 現状は `main` で作業。push すると公開が走るため、事前に `npm run lint` と `npm run build` を通す |
| フォント | 外部 CDN ではなく `@fontsource/*` を使う |
| 個人情報 | ご連絡フォームは練習用。本物の個人情報を入力・コミットしない。サンプル連絡先は `.example` ドメイン等の架空値を使う |
| 秘密情報 | `.env*` は `.gitignore` 済み。現状の環境変数は `PAGES_BASE_PATH` のみ（CI が設定） |
